目标与现状差距

来源: apps/daemon/src/db.ts · apps/daemon/src/routes/** · deploy/README.md · packages/contracts

现状：Open Design 是本地单用户客户端。daemon（Express）是唯一数据权威，项目文件落在 .od/projects/<id>/ 磁盘，SQLite 只存元数据（27 张表）；唯一的「认证」是共享令牌 OD_API_TOKEN，没有用户、组织、权限、同步概念。

目标总体架构

来源: 目标设计 · 保留现有 daemon/web/desktop/packaged 拓扑，新增云端服务与同步层

改造遵循「离线优先（offline-first）」原则：本地 daemon + 本地 SQLite 仍是离线时的工作权威（agent 运行、文件编辑、预览渲染都留在本地），云端 PostgreSQL 是跨设备共享权威。两者通过变更日志（outbox）+ 游标（cursor）增量同步。

新增三大横向能力：身份与认证（JWT）、团队与权限（组织/成员/角色）、同步引擎（元数据变更 + 文件块上传）。

分层职责对照

客户端运行时（保留）

本地单机行为不变，agent 运行与渲染仍在本机。

  • apps/daemon保留：项目/会话/文件/路由权威
  • apps/web保留：UI + 新增登录/组织/同步状态视图
  • apps/desktop保留：Electron 外壳，新增令牌安全存储
  • apps/packaged保留：打包侧车启动
同步与身份层（新增）

daemon 内新增的横向能力，全部走 HTTP，不侵入现有业务路由。

  • sync-engineoutbox 采集 · push/pull · 冲突处理
  • auth-clientJWT 获取/刷新 · 设备注册 · 离线缓存
  • file-chunker大文件分块 · 断点续传 · 内容寻址
  • version-store文件版本历史 · 恢复
云端服务（新增）

独立可部署服务，PostgreSQL 为共享权威。

  • apps/cloudExpress 服务 · /api/cloud/* 命名空间
  • auth注册/登录/JWT/刷新/登出/设备
  • orgs组织/团队/成员/邀请/角色
  • sync变更日志接收 · 游标推进 · 广播
  • files对象存储 · 块上传 · 版本
关键决策：云端服务以 /api/cloud/* 独立命名空间托管在 apps/cloud（新 workspace 包），与现有本地 /api/* 严格分离；daemon 通过 packages/contracts 中的 DTO 与云端通信，避免两套协议漂移。

身份与认证

来源: 现状 apps/daemon/src/api-token-auth.ts（仅共享令牌） → 目标：邮箱/用户名 + 密码 + JWT

现状 OD_API_TOKEN 是机器级共享令牌，无法区分用户。改造为用户级 JWT 体系：注册 / 登录签发 access_token（短期）+ refresh_token（长期，可轮换）；每个设备注册一个 device_id，用于游标隔离与多端管理。

令牌生命周期存储用途策略
access_token (JWT)15 分钟内存 / 安全存储调用云 API过期自动用 refresh 换取

离线优先同步引擎

来源: 目标设计 · outbox 模式 + 游标增量 + 冲突处理

同步引擎驻留在 daemon 内，监听本地数据库的写操作：每次业务写先在本地事务里落库并追加一条 outbox 记录（含 entity_type / entity_id / op / payload / device_id）。在线时批量 push 到云端；同时按设备游标 pull 云端新增变更回放本地。冲突采用按实体 LWW（updated_at + 服务端 rev），文件冲突则保留双版本而非覆盖。

同步循环（8 步）

1
本地写入即记录
业务路由写 SQLite 时，同一事务追加 outbox 记录 —— 不额外改业务代码，通过统一写入口钩子实现。
2
联网触发 push
daemon 检测到网络可达（或定时 30s / 写后 2s）→ 批量 POST /api/cloud/sync/push。
3
服务端校验与落库
云端校验用户权限 → 事务应用变更 → 写 change_log → 返回新游标。
4
确认与推进游标
客户端把 outbox 标记为已确认，device_cursor 推进到服务端返回的 seq。
5
pull 增量
since_cursor 之后的新变更回放本地；其他设备 / 在线协作者的修改在此进入本地。
6
文件变更按需拉取
元数据变更到达后，若文件块本地缺失 → 从对象存储分块下载落盘。
7
冲突处理
元数据按 updated_at + 服务端 rev LWW；文件内容冲突 → 保留双方版本，标记冲突待用户裁决。
8
多设备游标隔离
每设备独立 sync_cursors，多台机器各自增量，互不重放。
幂等与断点续传：push 请求携带 device_id + from_cursor，服务端按 change_log.seq 全局有序推进；某条失败不影响后续，客户端重试只补未确认区间。

安全模型

来源: 现状 api-token-auth.ts · 仓库安全边界 → 目标：用户级鉴权 + 权限判定
云端鉴权（新增）
  • argon2id密码哈希，慢哈希防爆破
  • JWT + refresh短时 access + 可轮换 refresh
  • 速率限制登录/注册端点限流防撞库
  • 全站 TLS反代终止，SSE 不压缩不缓冲
权限判定（新增）
  • PERM 层服务端唯一判定，不信任客户端声明
  • 行级隔离SQL 一律带 owner/org 过滤
  • 对象存储 ACL预签名 URL 限时有效
  • 审计change_log 含 actor 与设备，可追溯
本地边界（保留 + 加固）
  • loopback 绑定本地 daemon 仍仅监听回环
  • 令牌落盘加密文件 + OS 权限保护
  • 路径校验沿用 projects.ts 防穿越逻辑
  • SSRF 策略沿用外部 fetch 边界
