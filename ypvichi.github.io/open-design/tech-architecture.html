架构概览

来源: AGENTS.md · pnpm-workspace.yaml

Open Design 是一个由 pnpm workspace 管理的单体仓 (monorepo)，运行时目标为 Node ~24 + pnpm@10.33.2。仓库由四类 workspace 入口构成：apps/*、packages/*、tools/*、e2e，外加若干顶层内容目录。

核心运行时由 daemon（本地特权守护进程 + od CLI）统一承载 HTTP API、Agent 编排、技能、设计系统与产物；web（Next.js 16 App Router + React 18）通过同一组 /api/* 端点与 daemon 通信；desktop 与 packaged（Electron）作为外壳发现并托管 web URL。

应用层 Apps

来源: apps/AGENTS.md · AGENTS.md Workspace directories
apps/web

Next.js 16 App Router + React 18 Web 运行时。不直接依赖 daemon 源码，通过 /api/* + packages/contracts 集成。

  • App Router页面路由与渲染
  • @open-design/components源码级 transpile 共享组件
  • i18n19 个 locale，types.ts 为类型 Dict
  • artifactsquestion-form / TodoWrite 渲染
apps/daemon

本地特权守护进程 + od bin。承载 /api/*、Agent 生成、技能、设计系统、产物、静态服务。

  • server.ts解析 OD_DATA_DIR → RUNTIME_DATA_DIR
  • routes/25+ 路由模块（见路由表）
  • runtimes/defs/28 个 Agent 适配器定义
  • cli.tsod CLI，SUBCOMMAND_MAP 注册
apps/desktop

Electron 外壳。通过 sidecar IPC 发现 web URL，不承载业务逻辑。

  • sidecar IPC发现并加载 web 运行时
apps/packaged

打包版 Electron 薄入口。启动打包 sidecar，仅持有 od:// 入口胶水代码。

  • od:// 入口打包运行时胶水
  • 命名空间数据根解析后注入 OD_DATA_DIR
apps/landing-page

独立静态 Astro 营销与公开目录站点。构建期读取仓库内容，不参与 daemon/web 产品运行时。

  • Astro 静态构建期内容聚合

包层 Packages

来源: packages/AGENTS.md · AGENTS.md 边界约束
packages/contracts

纯 TypeScript Web/Daemon 应用契约层。承载共享 API DTO、SSE 事件联合、错误形状、任务形状。禁止依赖 Next.js / Express / Node fs / 浏览器 API / SQLite / daemon 内部 / sidecar 控制面。

packages/sidecar-proto

Open Design sidecar 业务协议。定义 sidecar 进程戳记五字段：app、mode、namespace、ipc、source。

packages/sidecar

通用 sidecar 运行时。承载进程生成、IPC、命名空间隔离等通用原语。

packages/platform

通用 OS 进程原语。跨平台进程扫描、信号、路径解析等底层能力。

packages/components

共享 UI 组件库（@open-design/components）。web 在 dev 期源码级 transpile，组件与 CSS Module 编辑走正常 web 开发循环。

packages/launcher-proto

启动器协议。定义打包/桌面启动器与编排层之间的契约。

packages/plugin-runtime

插件运行时。承载插件加载、生命周期、沙箱边界。

packages/registry-protocol

注册表协议。定义插件/技能/设计系统的注册与发现契约。

packages/host

宿主抽象。承载宿主环境能力暴露与适配。

packages/agui-adapter

AGUI 适配器。将 Agent 生成 UI 事件适配为可渲染组件树。

packages/download

下载能力包。承载产物/资源下载与进度反馈。

packages/diagnostics

诊断能力包。承载运行时健康检查、错误归因与上报。

packages/metatool

元工具包。承载工具元数据描述与动态工具暴露。

packages/release

发布数据契约。发布元数据、存储发布、发布报告与通知向数据契约（产物构造与冒烟在 tools/pack）。

工具层 Tools

来源: tools/AGENTS.md · tools/pack/AGENTS.md
tools/dev

本地开发生命周期控制面。唯一本地开发入口 pnpm tools-dev。拥有 sidecar 运行时/日志/IPC 命名空间；端口由 --daemon-port / --web-port 治理，导出 OD_PORT / OD_WEB_PORT。

tools/pack

打包构建/启停/日志控制面、打包更新器 harness、安装器身份/注册表校验面、mac beta 发布产物准备面。调用包原语，不手搓 --od-stamp-* 参数。

tools/serve

本地 fixture 服务控制面。首个服务 tools-serve start updater 提供确定性更新器元数据与产物。

tools/release

发布元数据、存储发布、发布报告与通知向数据契约所有者。产物构造与冒烟测试留在 tools/pack。

数据目录契约

来源: AGENTS.md Daemon data directory contract

daemon 启动时由 apps/daemon/src/server.ts 将 OD_DATA_DIR 解析为 RUNTIME_DATA_DIR，作为唯一活跃数据根真源。所有 daemon 数据路径必须派生自 RUNTIME_DATA_DIR 或其派生常量（如 PROJECTS_DIR、ARTIFACTS_DIR）。

路径性质说明
RUNTIME_DATA_DIR唯一活跃数据根由 OD_DATA_DIR 解析而来
PROJECTS_DIR派生常量托管项目根；导入文件夹项目例外，用 metadata.baseDir
ARTIFACTS_DIR派生常量产物根
SQLite · app config · memory · MCP config/tokens · automation state · plugin state · connector creds · generated files · logsdaemon 数据必须留在解析后的数据根下
Agent 子进程继承接收 OD_DATA_DIR 作为真源，不自猜路径
OD_MEDIA_CONFIG_DIR窄覆盖仅 media-config.json，非第二数据根
OD_LEGACY_DATA_DIR迁移源仅遗留数据导入，非活跃数据根
CODEX_HOME 等外部工具 home集成输入非 daemon 运行时数据
禁止复用的逃逸模式：cwd 相对遗留目录的模块级默认值、defaultRegistryRoots() 重算数据根、依赖 openDatabase 回退而非传入解析根、脚本帮助文本建议具体遗留目录。修复时路由到 RUNTIME_DATA_DIR 或显式数据根参数。

发布通道模型

来源: AGENTS.md Release channel model · tools/pack/AGENTS.md
通道App 身份定位
betaOpen Design Beta每日 R&D/开发验证，快速反馈，非稳定晋升门
prereleaseOpen Design Prerelease稳定交付的内部验证通道；稳定发布仍由 prerelease 产物门控
previewOpen Design Preview独立早期访问，类稳定严谨度；用 X.Y.Z-preview.N，发 preview R2 通道与 preview/latest 更新源
stableOpen Design正式交付通道；不依赖 preview，仅依赖 prerelease
Windows beta 更新器验证必须使用真实 beta 命名空间 release-beta-win，否则本地 beta-like 命名空间会创建独立卸载注册表项却看起来像同一个 Open Design Beta 应用。mac DMG 的拖拽安装 bundle 不得为 Open Design.app。
